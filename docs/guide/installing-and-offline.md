# Installing and offline play

[Back to README](../../README.md)

Hexathlon is a Progressive Web App. Once loaded over HTTPS it can be
installed like an app and played without a network connection.

## Installing

Use the browser's own install option, for example:

- **Chrome or Edge (desktop):** the install icon in the address bar, or the
  menu's "Install Hexathlon".
- **Android Chrome:** the menu's "Add to Home screen" or "Install app".
- **iOS Safari:** Share > "Add to Home Screen".

The web app manifest (`manifest.webmanifest`) names the app Hexathlon, asks
for full-screen display (falling back to standalone), sets the dark navy
theme and background colour, and lists the app icons in `icons/`: an SVG,
192 and 512 px icons, maskable versions for Android's adaptive shapes and a
monochrome version for themed icons. It also has screenshots for the richer
install dialog. The icons are code-defined art, generated by `pnpm icons`.

For the page's SEO tags, social preview images and the full icon set, see
[SEO, social previews and icons](../seo-and-icons.md).

## Offline play

The service worker, `sw.ts`, caches every file the game needs when it
installs: the page, the stylesheet, the manifest, the icons, the game's one
bundled script and the Attract Mode demos. Its list is generated by the build
from what the page loads. After the first visit the
game loads from that cache, so it plays offline.

- The worker registers only in a secure context (HTTPS, or `localhost`).
  The game works without it; offline play is optional.
- All paths are relative to `sw.ts`, so the game works under a subpath such
  as a GitHub Pages project site.
- **Deployed:** the deploy job builds with the commit SHA as the worker's
  `VERSION` (`SW_VERSION`). Each release therefore gets a fresh cache (`hexathlon-<sha>`), and
  the old cache is deleted when the new worker activates. Files are served
  cache first.
- **Locally** the version stays `dev` and the worker goes to the network
  first, so your edits show on reload; the cache is used only when offline.

Settings, controls, Personal Bests and High Scores live in local storage, not
in the cache, so they survive updates. See
[Settings](settings.md#what-is-stored).

If you add a file the game loads at runtime other than by import, have
`build.ts` copy it into `dist/`. `test/pwa.test.ts` fails if one is missing. See
[Development](development.md#adding-a-runtime-file).

## Browser support

The target browsers (from the
[product requirements](../product-requirements-document/))
are:

| Platform | Browsers |
|---|---|
| Desktop | Latest Chrome, Edge, Firefox and Safari |
| Mobile | iOS Safari and Android Chrome (touch controls, one player) |

Screens from 360 pixels wide up to 4K are supported: the 320x240 picture is
letterboxed and scaled to fit.

The game needs:

- ES modules, including JSON modules (`import ... with { type: 'json' }`),
  which the simulation uses to load `data/*.json`;
- Canvas 2D;
- Web Audio for sound (the game still plays without it);
- the Pointer Events API for touch, and the Gamepad API for pads (both
  optional);
- `localStorage` to keep anything between visits (optional: without it the
  game keeps everything in memory for the visit);
- service workers for offline play (optional).

Full Screen uses the browser's full-screen mode where there is one, and
otherwise just stretches the picture to fill the window.
